# Escape the Old Schoolhouse

A browser-based educational escape room for an introductory Foundations of Education course (philosophies and philosophers of education). Students solve 5 rooms; the certificate shows the exit password `DEWEY1916` for an auto-graded LMS quiz.

## Layout
- **Source (edit these):**
  - `src/game.html`: the student game engine. It draws each room as a 2D night scene ("dark tactile puzzle box") from a content object; it holds no course content itself.
  - `src/editor.html`: the teacher editor. It opens on the **guided steps** (the wizard: one question per page, see "The guided steps" below); the curator's workbench (a field for every content value, review tracking, preview, export to .html and SCORM .zip) is **Advanced mode**.
  - `src/shared.js`: logic used by both, and by Node: matching-code calculation, validation, review counts, content encoding, zip/SCORM writer, and the accessibility helpers (`ER.a11yHow(room)`: one plain sentence on how to work a room's lock; `ER.a11yDescribe(room, state)`: the "Describe this room" text as sections; `ER.a11yCheck(cfg)`: advisory notes for teachers about content that is hard to use, `[{ room, message }]`, never blocking). New shared accessibility helpers go under `ER.a11y…`.
  - `content/foundations-of-education.json`: the sample escape room's content.
- **Generated by `npm run build` (commit them, never edit by hand):** `index.html` (game + sample content), `editor.html`, `EscapeRoom_SCORM.zip`, `imsmanifest.xml`. Each output is one self-contained file: it must work by double-clicking and inside Moodle/Canvas. CI fails if they're out of date.
- Content is embedded in the game as base64 JSON in `<script id="escape-config">`. `ER.configFromHtml()` reads it back, so exported games can be reopened in the editor.
- `scripts/serve.js`: zero-dependency static server. `tests/playthrough.js`: automated play-through. `tests/a11y-game.js`: the game's accessibility tests. `tests/wizard.js`: the guided steps.
- `ACCESSIBILITY.md`: the accessibility statement (target, what was tested, measured contrast, known limitations). Keep it true: update it when a test, a figure or a limitation changes.

## Testing the web version
- `npm install` once (installs Playwright), then `npx playwright install chromium`.
- `npm test` builds, then runs `tests/playthrough.js` (plays the sample game: full run, SCORM reporting, wrong answers, hints, phone, desktop and short-frame layouts, no outside requests, the books/portraits looks, the dial lock by keyboard, the examine view, the rubber stamps, sound on/off and no-audio browsers, the notebook, lock and certificate effects, reduced motion, the Motion switch), `tests/a11y-game.js` (see "Accessibility (game)" below; `npm run test:a11y` runs it alone, `--only <text>` runs matching tests, `--report file.json` writes counts and the contrast table without failing, `--url <url>` tests another build, `--snapshots <dir>` writes each state's accessibility tree) and `tests/editor.js` (drives the editor: review tracking, text-mode quiz, validation, preview, .html and SCORM export, reopening an export, accuracy grading, the matching-room look selector, the phone cabinet drawer, the ⓘ help slips by keyboard, the pinned not-checked note, the answer-key envelope, adding a room, the slips that ask before deleting or replacing, the accessibility check's rules and page, and no outside requests; it opens Advanced mode with `editor.html?mode=advanced`), then `tests/wizard.js` (the guided steps: the whole journey from the sample to a Moodle grade file and the Canvas password route, the linked error summary, the exit-password slip, leaving and coming back to the hub, two escape rooms side by side, the backup reopening, the leave warning, phone width, no outside requests). `tests/a11y-editor.js` is the editor's accessibility suite (see "Editor accessibility" below); it takes a few minutes, and `A11Y_VARIANTS=default A11Y_TEST=<regex> node tests/a11y-editor.js` runs part of it. `BROWSER=webkit node tests/editor.js` runs the editor tests in WebKit. Screenshots go to `tests/screenshots/`. Look at them after visual changes.
- `npm run serve` serves the game at http://localhost:8080.
- **Playwright MCP** (`.mcp.json`): start `npm run serve`, then use the `playwright` MCP tools to open http://localhost:8080 (game) or http://localhost:8080/editor.html (editor: the guided steps; add `?mode=advanced` for Advanced mode), try it, resize to a phone width (390×844), and take screenshots. ### Sample answer key (for testing)
Room 1 `LEARN` · Room 2 `9154` · Room 3 oldest→newest: Plato, Rousseau, Mann, Montessori, Dewey, Freire, Adler · Room 4 top→bottom T,P,T,P,T,P,T,P · Room 5 any answers.

## Room types
Each type is an object the player handles. Every gradable item has `source` and `verified`.
- `matching`: objects with codes plus clue cards; the code is the codes of the clue cards in clue order (`codeWord` or per-card `code` override the automatic letters/numbers). It is entered on the **combination padlock** (one dial per character). Optional `look`: `"cards"` (default, a catalogue drawer) | `"books"` (books lying in piles on a shelf, spines out, so titles read left to right) | `"portraits"` (a gallery wall). Presentation only, resolved by `ER.look(room)`, which falls back to cards for unknown values or book names over 48 characters.
- `quiz`: question slips in a strongbox; short answers (`|`-separated accepted answers) are typed on a typewriter line, multiple choice (`correct` index) is a row of levers.
- `ordering`: items listed in correct order, shown scrambled as cards on a timeline string; solved cards get their `label` stamped on.
- `sorting`: slips with a `category` index, stamped with rubber stamps.
- `reflection`: the mirror asks one question at a time; options point at `profiles[].key`. Nothing moves on by itself: `#try` reads "Next question" until the last question, then the room's button label. The mirror itself is decoration.

To add a type, update `ER.validate`, `ER.reviewItems`, the renderer in `src/game.html`, the form in `src/editor.html`, the review sheet, and the tests.

## Hints, answers and preview
- Hints are per room: `hintsEnabled` (default **false**) and at most 2 entries in `hints`. They unlock after `hintRules.first` / `hintRules.second` wrong tries in that room (defaults 1 and 3). Reflection rooms never show hints. `ER.hintWarnings()` flags hints that give the answer away; keep sample hints as leading nudges, never the answer.
- `ER.answerKey(room)` is the single source for the editor's answer key, the preview's "Show answers" strip, and tests.
- The editor's preview builds the game with `__preview: true`. Only then does the game accept `postMessage` commands (`{er:"goto", room}`, `{er:"key", on}`) and send `{er:"room"}` / `{er:"escape"}` / `{er:"key", on:false}` back. `goto` changes the room without moving focus (the rail keeps the keyboard). Exported games must never contain `__preview` or show answers.
- "Show answers" draws `aside#teacher-key` (labelled by its `h2#tk-h`) **in the page flow** between `#hud` and `#stage`, never as an overlay, so it can't cover a focused control. Its `#tk-hide` button turns it off and sends `{er:"key", on:false}`; the editor then unchecks `#preview-answers` and focuses it.

## The scene (game)
- **One full-window scene; the page never scrolls, the room does.** `#scene` holds the painted wall and door (`#bg`), the lamplight (`#light`) and film grain (`#grainfx`), then `#view`, the scrolling column that holds the HUD (`header#hud`) and the room (`main#stage`). **The light, vignette and grain sit behind the objects** (they light the wall, door and floor): nothing is ever laid over text, because that is what broke contrast before. `<html data-screen>` is `title`, `room` or `end`, and `data-type` is the room type.
- **Text size is the reader's.** Every size is in `rem` and the root font size is never set by script, so the browser's font size and zoom work. `fit()` only sets `<html data-shape>` from how many text-widths fit: `wide` (60em or more: objects left, the locked door and its lock right, the lock sticky) or `tall` (one column: phones, narrow frames, and any window once text is enlarged). Don't size anything from the window, and don't give inner panels their own scrolling or a fixed height: content must be free to grow, and `#view` scrolls. `#more` is the "more below" mark.
- **Everything is flat 2D**, drawn in front view with CSS gradients, inline SVG and procedural textures (`--grain`, `--pgrain` (the much lighter grain for paper), `--wood`, `--woodh`, `--cork` are SVG `feTurbulence` data URIs). **No CSS 3D** (`perspective`, `rotateX/Y`, `translateZ`, `preserve-3d`) and no WebGL. Depth is faked with 2D tricks: parallax layers, `scaleX` plus `skewY` for doors, sliding strips for dials, squash and overshoot, and scale with a growing shadow for the examine view.
- **HUD:** `#skip` (skip link), `#doors` is the key ring (one `.door` key per room; `.open` is brass with a tick, `.current` is larger with a lamp dot; its `aria-label` summarises progress), `#draft` is the pencilled Draft note (a button with one fixed name; it unfolds `#draft-more`, which it controls with `aria-expanded`/`aria-controls`), `#sound-toggle` is the bell (a `role="switch"`), `#watch` is the pocket watch that opens the notebook, and `#timer` (`role="timer"`) sits under it.
- **Notebook (`#pause`)**: Esc or the watch. It stops the clock and holds `#resume`, the switches `#sound-toggle-2`, `#motion-toggle`, `#contrast-toggle`, `#readable-toggle`, `#clock-toggle` (each `role="switch"` with `aria-checked`, a `.lbl` name and a visible `.st` on/off word; set with `setSwitch()`), `#restart`, `#hintCount`, and "How to play". In the editor's preview, Esc closes the preview instead.
- **Papers and the examine view (`#examine`)**: a paper (story note, clue card, hint, house rules, result) keeps its words as ordinary text; its short heading button (`.story .go`, `.icard .no`, `.hint .hb`, `.rules .rb`, `.result .h`, rendered with `ex(html)`) opens it large, and CSS stretches that button over the whole paper. Books, portraits and plain cards are whole buttons named "Code L: Essentialism". Esc, the close button or a click outside puts a sheet back and returns focus. While a sheet or the notebook is open `#scene` is `inert`. Never open one automatically: it covers the room, and the tests click straight through.
- **Describe this room (`#describe`)**: under each room's title; opens a sheet built from `ER.a11yDescribe(room, roomState())` (`roomState` is set by the ordering and sorting rooms so the description follows what the player has done). A new room type needs a branch there and in `ER.a11yHow`.
- **Locks.** Matching rooms use `dialLock()`: `.dial` elements (`role="spinbutton"`, `aria-valuetext` like "E, 5 of 26"; arrow keys, typing (which says "Dial 2: E" and moves to the next dial), wheel, drag, or the `.nub` arrows, which act on release) kept in step with the real text field `#answer` (labelled "Type the whole code instead"); the lock's brass name `.lname` is its `h3`; DOM and Tab order are dials, `#answer`, then `#try` (the shackle, drawn on top with CSS `order`). Every other room uses `keyLock()`: `#try` is a safe handle with a paper tag, plus a `#counter` that shows how many were right. The room wrapper has class `.lock` and gets `.unlocked` or `.nope`. Under every lock `#how` says how to work it (`ER.a11yHow`): it names the real button (“Check answers”, “Check order”, “Submit”, “Pull the shackle”), never only the picture, and for matching rooms says to take the clues in order (and that some objects are decoys, when they are). Feedback text always goes to `#msg` through `setMsg()`, which announces it and scrolls it into view (the `#more` tab steps aside from it and from the focused control).
- **After a solve nothing moves on by itself.** `pass()` keeps the result in `#msg` and the live region and calls `onward()`, which adds `#onward` ("Go through the door", a brass `.pushplate`) under it and focuses it; pressing it calls `go(n+1)`. The last room's plate leads to the certificate. Tests press `#onward`. "Play again" on the certificate asks first, like "Start over".
- **Fonts:** three faces, embedded as base64 woff2 in the `<style>` block at the end of `src/game.html` with their licence notices. `--f-r`, **Atkinson Hyperlegible** (OFL; regular, bold, italic) is the reading face: stories, clues, questions, answers, hints, codes, dial characters and every digit. `--f-d`, IM Fell English SC (OFL), is for short labels only. `--f-ty`, Special Elite (Apache-2.0), is decoration for a few tags of at most four words. `--f-t` is an old name that now points at the reading face. IM Fell's digits are excluded with `unicode-range` because its 1 reads as a capital I; keep it that way. Reading text is 1rem or more with line height 1.5; nothing is under .8rem.
- **No emoji as icons.** Icons are inline SVG. A picture character at the start of a teacher's lock label or message is dropped by `deco()`, because the game draws its own.

## Motion
- Motion is no-motion-first. The still version is the base CSS. `[data-motion=off] *` switches off every animation and transition, idle animations sit inside `@media (prefers-reduced-motion: no-preference)` under `[data-motion=on]`, and every scripted effect (dial slide, lock rattle and drop, door, stamps, fog, parallax, confetti) checks `calm()` first. `<html data-motion>` is set by the script from the OS setting and the notebook's **Motion** switch (`#motion-toggle`, remembered in `localStorage` inside try/catch). The reduced-motion test asserts `document.getAnimations().length === 0`.
- New effects need a no-motion path, should animate only transform/opacity with `element.animate()`, must clean up after themselves, and must stay 2D.
- Room changes go through `go(n)`: the lantern dims, the screen is swapped in the dark, and two door leaves (`#doorfx`) part while the room rises. With motion off the next screen simply appears. `show()` inside it does all the work, so focus, hints, SCORM and the preview's `goto` behave the same on every path. The next screen can appear up to about 150 ms after `go()` is called, so tests should wait for it rather than read the page at once.
- Decorative pieces (book bands, portrait frames, lantern, seal, door, dust) are `aria-hidden`. The term and code of every object stay real text ("Code L: Essentialism").

## Accessibility (game)
The target is WCAG 2.2 AA with no exceptions, AAA where practical; accessibility wins over the art direction. `ACCESSIBILITY.md` is the public statement and `tests/a11y-game.js` holds the line. That test walks every screen and state (`tour()`: add new states there) and checks axe-core (zero violations, in the normal look, High contrast, Readable text, forced colours, `prefers-contrast: more`, two window sizes), a keyboard-only play-through, focus rings and focus never covered, target sizes, 200% text, 320px reflow, the text-spacing override, controls still drawn in forced colours, announcements, names/roles/states, and **contrast measured from screenshots** (`TEXTS` lists the text styles: add new ones; reading text must measure 7:1, everything else 4.5:1). It also runs in WebKit.
- **Contrast is measured, not assumed.** Text sits on textures, so check the measured figure after any colour, texture or lighting change. Paper uses `--pgrain`; brass that carries text uses `--plate` or `--brassy` (both light enough for dark text everywhere). Stamp inks (`INKS`) and `--redink` are dark enough for 4.5:1 on paper.
- **Focus.** One two-tone ring for everything (`:focus-visible, .kf:focus` at the end of the main `<style>`, with `!important`); don't add per-element focus colours. `.kf` is added by script to whatever takes focus while the keyboard is in use, because Safari doesn't apply `:focus-visible` to focus moved by script. Never use `clip-path` on something focusable (it clips the ring). A focused control is scrolled into view by a `focusin` handler on `#view`.
- **Targets.** Game controls are 2.75rem (44px) or more; everything else at least 24px.
- **Announcements.** `say(text)` writes to the one polite live region `#live` (it empties it first, so a repeated message is read again). Nothing clears it on a timer; `hush()` empties it silently when the screen changes. Don't add `role="status"` or other live regions. Results, moved cards, stamps, hints, dial values typed and switches are announced.
- **Room changes.** `go()` sets `document.title` ("Room 2 of 5: … · game") and moves focus to the new screen's `h2`, which reads the room out; it is **not** announced again through `#live` (only if there is no heading to focus). Keep exactly one `h2` in `#stage`; parts of a room are `h3` (matching rooms: the objects (screen-reader only), the clues and the lock; other rooms: "The lock", screen-reader only); sheets start with an `h2`.
- **Nothing is cut short.** No `line-clamp` or fixed heights on stories, clues, house rules or results; the clipping test fails on any clamped text.
- **State is never colour alone**, sound is never the only feedback, and nothing changes context by itself. A locked control that should still be reachable uses `aria-disabled` (the hint drawer, the Motion switch under reduced motion, a solved lock's focused control), not `disabled`.
- **Options** live on `<html>`: `data-contrast="more"` (the High contrast switch, or `prefers-contrast: more`), `data-readable="on"`, `data-clock="off"`, next to `data-motion`. They are remembered in `localStorage` (`escape-room-contrast`, `-readable`, `-clock`) inside try/catch, with an in-memory fallback. High contrast sets the texture variables to `none`, hides `#light` and `#grainfx`, and gives every control a border; forced colours (`@media (forced-colors: active)`) does the same with system colours. A new control needs a rule in both blocks (the "still drawn" test checks for a real edge).
- **Order.** DOM order is reading order and Tab order. Where the picture wants something elsewhere (Begin on the door, the shackle above the lock), place it with CSS grid or `order`, not by moving it in the DOM.

## Sound
- `SND` synthesises every sound with Web Audio (`SND.play("tick" | "rustle" | "clack" | "thump" | "key" | "clunk" | "turn" | "creak" | "chime" | "thud" | "press")`). Nothing is downloaded. The audio context is created on the first key press or tap, and every call is wrapped so a browser with no audio stays silent without errors.
- Sound has its own switch (`#sound-toggle` in the HUD, `#sound-toggle-2` in the notebook), remembered in `localStorage` under `escape-room-sound`. It is independent of the Motion switch. Keep sounds short and quiet.

## The editor ("the Curator's workshop")
- Flat 2D art, dark and lamplit: an oak bench, a specimen **cabinet** of drawers (`#nav .item`, one per page or room), a felt blotter with the page on paper, and loose objects beside it (the pinned note, the answer-key envelope, a brass "Preview this room" plate). No CSS 3D (`perspective`, `rotateX/Y`, `translateZ`, `preserve-3d`); depth is faked with 2D slide, scale and shadow. Every transition and animation sits inside `@media (prefers-reduced-motion: no-preference)`.
- Fonts: IM Fell English, IM Fell English SC (both OFL) and Special Elite (Apache-2.0) are embedded as base64 woff2 in `<style id="fonts">` with their licence notice. The answer sheet copies that block into its own document. IM Fell's digits are excluded with `unicode-range`, so digits are typed in Special Elite. **The embedded faces are for short labels only** (`--display`, `--caps`, `--type`). Anything that is read or written (field values, help slips, notes, the answer key, the answer sheet) uses `--read`, a plain system serif; the quiz text box uses `--mono`.
- A page is `{ kicker, title, help, tabs: [{ id, label, help, body }] }`; `render()` draws the open index tab (`#tab-<id>`, remembered per page in `tabOf`). The gradable items are always the first tab (`#tab-items`).
- Controls are drawn, with real inputs underneath: `field()` is a visible label over an underline-only input (2px ink rule, never placeholder-only); `select()` is a brass selector made of radio buttons (`.rotary` in a `role="radiogroup"`, inside `.field[data-key=…]`; arrow keys are the browser's own); the verify control is a checkbox under a wax seal (`.verify label.chk`, named "I checked this is correct (Card 3)"); `toggle()` is a brass switch (`role="switch"` on a checkbox; the hints switch is `label.switch:has(#hints-toggle)`). Every ledger entry is a `role="group"` named "Card 3". Don't add boxed inputs, native `<select>`s, pills, callout boxes or helper paragraphs.
- Help text goes in `tip(text, about)`: an ⓘ button (a drawn SVG, named "Help: …") whose slip (`.pop`, `role="tooltip"`) opens on hover and focus, stays while the pointer is on the mark or on the slip, pins on click or Enter, and closes on Esc (without moving focus) or blur. The slip is always in the DOM (`hidden` when closed), is the button's and the field's `aria-describedby`, and while open is moved into the nearest landmark or dialog. Tests look for `.pop:visible`. `#look-help` is a screen-reader status line, not visible text.
- The not-checked warning is `#draft-note` (one line, `aria-expanded`) with `#draft-note-more` folded under it. The tally is `#meter` ("31 / 40 checked"). Each drawer label has a `.mark` ("3/8", or a tick) with hidden text ("5 to check").
- The answer key is `<details id="answer-key">` (the envelope) holding `.keycard`; it starts closed.
- At 51.25em (820px at the default text size) and below the cabinet is off-canvas; `#cabinet-handle` opens it (`body.cab-open`), and choosing a drawer, Esc, `#cabinet-close`, or the scrim closes it. While open, `#cab` (the box inside `<nav id="nav">`) is a `role="dialog"`. The file buttons move behind `#btn-more` (a disclosure). Breakpoints are in `em` so they follow the reader's text size; below 30em tall on a phone the whole page scrolls and nothing is pinned.
- Overlays (`overlay()`) are a manila `.folder` on the bench; the preview's teacher bar is the brass `.pbar` rail. `ask(title, lines, {ok, cancel, danger})` is the slip that replaces `confirm()` (`.modal[role=alertdialog]`, `#ask-cancel` focused first, `#ask-ok`; resolves `true` or `false`), and `tell()` replaces `alert()`. **Never call `confirm()`, `alert()` or `prompt()`**; the tests fail on any native dialog.
- Every modal layer (folders, slips, the preview, the phone cabinet) goes through `modalOpen(el, onEsc, opener)` / `modalClose()`: everything behind it becomes `inert` (except elements marked `data-keep`), Tab loops inside, Esc closes the top layer, and focus returns to the opener.
- Icons are inline SVG from `ICONS` via `icon(name)`. No emoji in the editor's own interface (teachers may still type them as card icons).

### The guided steps (the wizard)
- `<html data-mode>` is `wizard` or `advanced`, set before first paint from the address: `#advanced` (optionally `&room=N` or `&page=settings|intro|finish|a11y`) or `?mode=advanced` opens Advanced mode; anything else the wizard. Wizard pages are hashes: `#step=welcome|start|name|rooms|add|room|facts|try|deliver|walk|done|hub`, with `&room=N&part=questions|cards|clues|story|advanced` for rooms (N is 1-based). `hashchange` drives `routeTo()`, so browser Back works; change page with `wizGo(hash)`, never by re-rendering by hand. Unknown hashes (the skip link) are ignored; an empty hash goes home (the hub if anything is saved, else Welcome). `#btn-guided` (in Advanced mode's file list) goes back to the hub.
- The DOM is `#wizard` (after `#main`): `.wtop` (`role="banner"`, the save line `#wiz-save`), `#wiz-steps` (`role="navigation"`: an `<ol>` in a `<details>`, `aria-current="step"`, folded on phones) and `#wiz-main` (`role="main"`) holding `.paper.wsheet#wiz-sheet`. The landmarks are roles on `div`s so the workshop's `header`/`nav`/`main` CSS never reaches them. The look is calmer than Advanced mode: one column of paper, 1.125rem reading text, the question in the plain reading serif, one brass button.
- A step is `WSTEPS[id] = { title(r), body(r), check(r) → [{ key, target, text }] or [{ href, text }], gate?, save?, next(r), back?, go? (button text), cap?, continue: false? }`. `renderWizard(focus)` draws `#wiz-form` (a real `<form>`, so Enter continues): `#wiz-backlink`, `#wiz-cap` ("Step N of 10"), the error summary `#wiz-errors` ("There is a problem"; each link focuses its `target`), the body, `#wiz-continue` and `#wiz-back`, then the foot: `#wiz-later` (Save and finish later → hub) and `#wiz-advanced` (Show all settings). The question is always `#wiz-h1` (the field's label, or inside the radios' `<legend>`); focus goes there on every page change, and to `#wiz-errors` after a failed Continue. `document.title` is `[Error: ]Step N of 10: question – Escape room maker`.
- Builders: `wField({ id, label, set, hint, area, asH1, item })` (an edit calls `wUnverify(item)`; nothing in the wizard ever verifies), `wRadios({ name, legend, asH1, options: [{ value, title, desc, eg, pic, reveal }] })` (real radios over drawn slips, ids `name-value`), `wHelp()` (`#wiz-help`, "Help with this step"), `wbtn()` (always `type=button` inside the form). No callout boxes, pills or emoji: errors are red ink between double rules.
- Rooms: `PARTS` (`quiz`: questions, story; `matching`: cards, clues, story; any other kind: one `advanced` page that links to `#advanced&room=N`). Ids: questions `qN-prompt`, `qN-kind-short|choice`, `qN-a0…` (accepted answers, stored as the `|` list), `qN-c0…`, `qN-okJ`, `qN-add-a`, `qN-add-c`, `qN-remove`, `#wiz-add-q`; cards `cN-term`, `cN-detail`, `cN-clue`, `cN-extra` (a card's optional `decoy` flag says it is an extra card on purpose; the game ignores it), `cN-up`, `#wiz-add-card`, `#wiz-lock-line`; story `#room-title`, `#room-story`; the list `#wiz-room-list`, `#wiz-room-change-N`, `#wiz-room-up-N`, `#wiz-room-remove-N`, `#wiz-add-room`; adding `kind-*`. Start: `start-sample|empty|file`, `#wiz-file`, `#wiz-file-btn`, `#wiz-file-name`, `#wiz-file-err`, `#wiz-start-note`, `#wiz-have-one`. Name: `#wiz-title`, `#wiz-course`. Facts: `#wiz-facts-count`, `#wiz-next-unchecked`, `#wiz-print`, `#wiz-ai-note`, `#wiz-warn` (`#wiz-check-now`, `#wiz-continue-anyway`), per item `fR-list-N-src` and `fR-list-N-ok`. Try: `#wiz-try`. Deliver: `where-*`, `how-quiz|scorm` (kept in the escape room's bookkeeping, `meta.delivery`, never in the content). Walkthrough: `#wiz-download`, `#wiz-downloaded`, `#wiz-password` (and `-copy`), `#wiz-password-later`, `#wiz-quiz-q`, `#wiz-quiz-a`, `.wtrouble` folds. Done: `#wiz-summary`, `#wiz-done-backup`, `#wiz-done-backup-note`. Hub: `#wiz-hub-title`, `#wiz-tasks` (`#task-name`, `#task-room-N`, `#task-add`, `#task-facts`, `#task-try`, `#task-deliver`, `#task-backup`, `#wiz-hub-backup`), `#wiz-lib` (`#lib-open-<id>`, `#lib-remove-<id>`), `#wiz-another`, `#wiz-copy`.

### Saving, backups and several escape rooms

### Editor accessibility (WCAG 2.2 AA is the floor; see ACCESSIBILITY.md)
- **Announcements:** `say(text)` writes to `#live` (a polite status region) when something changes that sighted teachers simply see: a seal pressed or lifted, an entry moved or deleted, a room added. `toast()` strips go in `#toasts`, which is also a live region, and stay six seconds (longer while pointed at); they only confirm something already done, and ACCESSIBILITY.md says so.
- **Focus:** choosing a drawer moves focus to the page heading (`#page-title`, described by the kicker) and sets `document.title`. `render()` keeps focus where it was by index; actions that move or remove things place focus explicitly (a moved entry keeps the keyboard, a deleted entry hands it to its neighbour). The cabinet is only redrawn when its signature changes (`navSig`).
- **Display options:** `#contrast-toggle` and `#readable-toggle` at the foot of the cabinet (`#display-toggles`). They set `<html data-contrast="more">` / `<html data-readable="on">` and are stored under `escape-room-contrast` / `escape-room-readable` (`"on"` / `"off"`), the same keys as the game, so the preview follows. High contrast also follows `prefers-contrast: more` until the teacher chooses, and is always on under `forced-colors`. A small script in `<head>` applies both before first paint.
- **High contrast and forced colours:** all High contrast rules are `html[data-contrast=more] …` and use real borders, never shadows or gradients, for edges and states. The `@media (forced-colors: active)` block maps the palette to system colours and marks "on" states with `Highlight`. Hide marks with `opacity` or `visibility`, not transparent `color` (forced colours repaint it).
- **Contrast:** the lamp (`.light`) and vignette (`.shade`) sit *under* the cabinet, rail and blotter (`z-index:1`), so they never dim text. Text is measured from screenshots in the tests; keep new text at 7:1 where you can and never under 4.5:1 (3:1 for large text and control edges).
- **Sizes:** every target is at least 24×24 CSS px, and 44×44 on touch screens (`@media (pointer:coarse)`). Sizes are in `rem`; body text is `100%`, never a fixed `px` size.
- **Accessibility check:** `a11yCheck(config)` returns `[{ rule, page, tab, where, text, quote }]` (rules: `missing-text`, `colour`, `position`, `shape`, `sound`, `device`, `time`, `caps`, `long-code`, `look-alike`, `many-items`, `symbol-only`, `long-text`, `reading-load`, `answer-list`, `above`, `no-hints`; limits in `A11Y_LIMITS`, word lists in `A11Y_WORDS`). It is advice only: it must never block preview or export. It is shown on the `a11y` page (`#a11y-summary`, `.notes li[data-rule]`), counted on its drawer, mentioned in the export folder (`#export-a11y`), and printed on the answer sheet (`answerSheetHtml()`, `#a11y`). Its rules are unit-tested in `tests/editor.js`; add a test with every new rule, including a "fair wording is left alone" case.
- **Placeholders** are examples that start with "e.g.", never instructions; they are lighter than typed text and an empty one-line field has a dashed rule.
- **The preview rail** (`.pbar`) is `flex:none`: it never shrinks below its controls; on short screens the preview scrolls instead.
- **Tests:** `tests/a11y-editor.js` scans every page, tab and overlay (`eachState()`; add new pages and overlays there), and every frame on its own (the answer sheet, and the preview's student view with the answer strip on), with axe-core at 1440×900 and 390×844 in five variants, measures contrast from pixels, checks target sizes and visible edges, tabs through every screen (focus ring, not obscured), runs a keyboard-only authoring test, and checks 200% text, 320px reflow, text spacing, reduced motion and the accessibility tree. Zero axe violations and zero "needs review" are required, except three kinds it leaves out on purpose and counts or explains: `color-contrast` (text on gradients and textures, measured from pixels instead), `frame-tested` (every frame is scanned on its own) and `heading-order` inside a frame. It also checks that the answer strip never covers a focused control in the student view, and that the rail keeps its controls inside it at 320×256 and with 32px text. `eachState()` ends with `wizardStates()`: every guided step and its variants (errors, revealed choices, the password slip, the hub with two escape rooms); add new steps there. A second keyboard-only test completes the guided steps from Welcome to the download.
