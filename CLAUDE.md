# Escape the Old Schoolhouse

A browser-based educational escape room for an introductory Foundations of Education course (philosophies and philosophers of education). Students solve 5 rooms; the certificate shows the exit password `DEWEY1916` for an auto-graded LMS quiz.

## Layout
- **Source (edit these):**
  - `src/game.html`: the student game engine. It renders rooms from a content object; it holds no course content itself.
  - `src/editor.html`: the teacher editor, drawn as a curator's workbench (a field for every content value, review tracking, preview, export to .html and SCORM .zip).
  - `src/shared.js`: logic used by both, and by Node: matching-code calculation, validation, review counts, content encoding, zip/SCORM writer.
  - `content/foundations-of-education.json`: the sample escape room's content.
- **Generated by `npm run build` (commit them, never edit by hand):** `index.html` (game + sample content), `editor.html`, `EscapeRoom_SCORM.zip`, `imsmanifest.xml`. Each output is one self-contained file: it must work by double-clicking, inside Moodle/Canvas, and inside the Mac app. CI fails if they're out of date.
- Content is embedded in the game as base64 JSON in `<script id="escape-config">`. `ER.configFromHtml()` reads it back, so exported games can be reopened in the editor.
- `mac/`: Swift (AppKit + WebKit) wrapper. CI (`.github/workflows/build-mac.yml`) builds it on macOS and publishes the `mac-latest` release from `main`.
- `scripts/serve.js`: zero-dependency static server. `tests/playthrough.js`: automated play-through.

## Testing the web version
- `npm install` once (installs Playwright), then `npx playwright install chromium`.
- `npm test` builds, then runs `tests/playthrough.js` (plays the sample game: full run, SCORM reporting, wrong answers, hints, phone layout, no outside requests, the books/portraits looks, lock and certificate effects, reduced motion, the Motion button) and `tests/editor.js` (drives the editor: review tracking, text-mode quiz, validation, preview, .html and SCORM export, reopening an export, accuracy grading, the matching-room look selector, the phone cabinet drawer, the ⓘ help slips by keyboard, the pinned not-checked note, the answer-key envelope, adding a room, and no outside requests). `BROWSER=webkit node tests/editor.js` runs the editor tests in WebKit. Screenshots go to `tests/screenshots/`. Look at them after visual changes.
- `npm run serve` serves the game at http://localhost:8080.
- **Playwright MCP** (`.mcp.json`): start `npm run serve`, then use the `playwright` MCP tools to open http://localhost:8080 (game) or http://localhost:8080/editor.html (editor), try it, resize to a phone width (390×844), and take screenshots. Use this to check layout and feel, not only the automated tests.

### Sample answer key (for testing)
Room 1 `LEARN` · Room 2 `9154` · Room 3 oldest→newest: Plato, Rousseau, Mann, Montessori, Dewey, Freire, Adler · Room 4 top→bottom T,P,T,P,T,P,T,P · Room 5 any answers.

## Room types
`matching` (cards with codes + clues; code = codes of clue cards in clue order; `codeWord` or per-card `code` override auto letters/numbers; optional `look`: `"cards"` (default) | `"books"` | `"portraits"`, presentation only, resolved by `ER.look(room)`, which falls back to cards for unknown values or book names over 48 characters), `quiz` (short answer with `|`-separated accepted answers, or multiple choice with `correct` index), `ordering` (items listed in correct order, shown scrambled), `sorting` (items with a `category` index), `reflection` (questions whose options point at `profiles[].key`). Every gradable item has `source` and `verified`. To add a type, update `ER.validate`, `ER.reviewItems`, the renderer in `src/game.html`, the form in `src/editor.html`, the review sheet, and the tests.

## Hints, answers and preview
- Hints are per room: `hintsEnabled` (default **false**) and at most 2 entries in `hints`. They unlock after `hintRules.first` / `hintRules.second` wrong tries in that room (defaults 1 and 3). Reflection rooms never show hints. `ER.hintWarnings()` flags hints that give the answer away; keep sample hints as leading nudges, never the answer.
- `ER.answerKey(room)` is the single source for the editor's answer key, the preview's "Show answers" panel, and tests.
- The editor's preview builds the game with `__preview: true`. Only then does the game accept `postMessage` commands (`{er:"goto", room}`, `{er:"key", on}`) and send `{er:"room"}` / `{er:"escape"}` back. Exported games must never contain `__preview` or show answers.

## The editor ("the Curator's workshop")
- Flat 2D art, dark and lamplit: an oak bench, a specimen **cabinet** of drawers (`#nav .item`, one per page or room), a felt blotter with the page on paper, and loose objects beside it (the pinned note, the answer-key envelope, a brass "Preview this room" plate). No CSS 3D (`perspective`, `rotateX/Y`, `translateZ`, `preserve-3d`); depth is faked with 2D slide, scale and shadow. Every transition and animation sits inside `@media (prefers-reduced-motion: no-preference)`.
- Fonts: IM Fell English, IM Fell English SC (both OFL) and Special Elite (Apache-2.0) are embedded as base64 woff2 in `<style id="fonts">` with their licence notice. The answer sheet copies that block into its own document. IM Fell's digits are excluded with `unicode-range`, so digits are typed in Special Elite.
- A page is `{ kicker, title, help, tabs: [{ id, label, help, body }] }`; `render()` draws the open index tab (`#tab-<id>`, remembered per page in `tabOf`). The gradable items are always the first tab (`#tab-items`).
- Controls are drawn, with real inputs underneath: `field()` is a label over an underline-only input; `select()` is a brass selector made of radio buttons (`.rotary`, inside `.field[data-key=…]`); the verify control is a checkbox under a wax seal (`.verify label.chk`); the hints switch is `label.switch:has(#hints-toggle)`. Don't add boxed inputs, native `<select>`s, pills, callout boxes or helper paragraphs.
- Help text goes in `tip(text, about)`: an ⓘ button whose slip (`.pop`, `role="tooltip"`) opens on hover and focus, pins on click or Enter, and closes on Esc or blur. `#look-help` is a screen-reader status line, not visible text.
- The not-checked warning is `#draft-note` (one line, `aria-expanded`) with `#draft-note-more` folded under it. The tally is `#meter` ("31 / 40 checked"). Each drawer label has a `.mark` ("3/8", or a tick) with hidden text ("5 to check").
- The answer key is `<details id="answer-key">` (the envelope) holding `.keycard`; it starts closed.
- At 820px and below the cabinet is off-canvas; `#cabinet-handle` opens it (`body.cab-open`), and choosing a drawer, Esc, or the scrim closes it. The file buttons move behind `#btn-more`.
- Overlays (`overlay()`) are a manila `.folder` on the bench; the preview's teacher bar is the brass `.pbar` rail.
- Icons are inline SVG from `ICONS` via `icon(name)`. No emoji in the editor's own interface (teachers may still type them as card icons).

## Look and motion
- Fonts: Schoolbell (chalk titles, Apache-2.0) and IM Fell English SC (small-caps labels, OFL) are embedded as base64 woff2 in the `<style>` block at the end of `src/game.html`, with their licence notice. They add about 100 KB to every game file. IM Fell's digits are excluded with `unicode-range` because its 1 reads as a capital I; keep it that way, since codes are digits.
- Motion is no-motion-first. The still version is the base CSS. Every animation rule sits inside `@media (prefers-reduced-motion: no-preference)` and under `[data-motion=on]`, and every scripted effect (sparks, lock rattle, confetti, room transition) checks `calm()` first. `<html data-motion>` is set by the script from the OS setting and the header **Motion** button (`#motion-toggle`, remembered in `localStorage` inside try/catch).
- New effects need a no-motion path, should animate only transform/opacity, and must clean up after themselves. Don't put a CSS `animation` on `.lock` or other direct children of `#stage`: changing it replays their entrance animation (use `element.animate()` as `lockMove()` does).
- Room changes go through `go(n)`: View Transitions API where available (the board swings like a door), else a short fade, else instant. `show()` inside it does all the work, so focus, hints, SCORM and the preview's `goto` behave the same on every path. The next screen can appear up to about 150 ms after `go()` is called, so tests should wait for it rather than read the page at once.
- Decorative pieces (book bands, portrait frames, padlock, seal, sparks, confetti) are `aria-hidden`. The term and code of every card stay real text ("Code L: Essentialism").
- A padlock emoji at the start of a lock label is not shown, because every lock row already draws a padlock.

## Content accuracy
- **Never mark content as verified (`"verified": true`).** Only the instructor does that, in the editor, after checking it against their sources. AI-written or AI-edited content always stays unverified.
- If you change an item's meaning, set its `verified` back to `false`.
- The game shows a "Draft" notice while anything is unverified. Don't remove or hide it.

## Rules for changes
- **No external requests**: no CDNs, web fonts, analytics, or images from URLs. The offline test enforces this.
- **Accessibility**: use real buttons and labels, keep everything keyboard-operable (no drag-and-drop-only puzzles), and keep text readable.
- **Accuracy matters**: this is course content. Double-check names, dates, quotes, and how each philosophy is described before changing them, and still leave them unverified for the instructor.
- Content is lightly obfuscated (base64) inside the game file. That only deters casual peeking; don't describe it as secure.
- Teachers edit content in the editor, so every content field must stay editable there. Don't hard-code course content in `src/game.html`.
- If you change the sample's answers, the exit password, room count, or element IDs (game: `#begin`, `#answer`, `#try`, `#msg`, `#hint-btn`, `#hint-note`, `#hints`, `#order`, `#exit-password`, `#draft`, `#teacher-key`, `#motion-toggle`, `#confetti`; editor: `#meter`, `#nav`, `#answer-key`, `#hints-toggle`, `#hint-warnings`, `#look-row`, `#look-help`, `#preview-room`, `#preview-exit`, `#cabinet-handle`, `#draft-note`, `#draft-note-more`, `#draft-line`, `#add-room`, `#add-menu`, `#tab-*`, `#btn-*`, `#export-*`, `#new-*`) or the classes the tests read (`.shelf .vol .letter b`, `.gallery .portrait .plate b`, `.icard`, `.mcard`, `.lock.unlocked`, `.lock.nope`, `.seal`), update the tests, the README answer key, and this file.
- No personal information (names, emails, school details) in any file or commit.
- The SCORM code must keep working when no LMS is present (the plain-browser case).
